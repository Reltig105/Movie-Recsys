### [2026-10-21] LightFM (WARP): офлайн-обучение и онлайн-выдача
* **Что сделано:**
  * `build_features.py` собирает CSR-матрицы из PostgreSQL: 200 949 × 87 585, 32 000 213 взаимодействий; гибридные признаки фильма (identity + жанры/режиссёр/актёры), 219 302 колонки.
  * `train_lightfm.py`: WARP, d=64, 10 эпох, порог «понравилось» ≥ 4.0 (15 938 238 положительных), обучение 4,3 мин на 12 потоках в Linux-контейнере.
  * Смещения свёрнуты в векторы (65-я координата), проверка воспроизведения: `max |predict − folded| = 9,54e-07`.
  * `backend/recommender/`: FAISS `IndexFlatIP` (топ-500 → 5 exploit + 2 explore), холодный профиль из оценок, исключение оценённого и фильмов без постера.
  * Redis-кулдаун показов на 24 часа (`rexter:shown:<user_id>`, sorted set) с откатом в память процесса.
* **Грабли:**
  * LightFM 1.17 не собирается и падает по WARP на Windows — обучение только в Docker (`python:3.11-slim` + OpenMP).
  * `faiss.read_index()` на Windows не открывает путь с кириллицей (`Документы`): C++ `fopen` не понимает UTF-8. Читаем байты через `np.fromfile` + `faiss.deserialize_index`.
  * Запущенный API держит `.npy` через `mmap`, поэтому перезапись артефактов с Windows-хоста возможна только после остановки сервера.
  * WARP не трогает пользователей без положительных оценок — им достаётся случайный вектор. При экспорте обнуляем такие строки (222 пользователя), и онлайн-контур собирает профиль из их фактических оценок.
* **Проверено:** персонализация различается между пользователями; повторная лента не пересекается с предыдущей (кулдаун); новый пользователь после 5 оценок получает осмысленную выдачу без оценённых фильмов; ни один из 1 926 фильмов без постера не попал в 500 рекомендаций.
* **Следующий шаг:** метрики ранжирования (`HitRate@K`, `NDCG@K`) на отложенной по времени выборке и деплой на VPS.
