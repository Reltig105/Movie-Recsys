# ML System Design: Movie Recommendation Service

## 1. Цели продукта и постановка задачи

### 1.1. Продуктовая концепция
Минималистичный сервис персональных рекомендаций кино (в эстетике издания «Чтиво») с акцентом на контент, отсутствие рекламного шума и возможность семантического поиска по настроению («по вайбу»).

### 1.2. Пользовательские сценарии (User Stories)
* **Сценарий 1 (Холодный старт / Новый пользователь):**
  * В профиле 0 оценок.
  * *Поведение системы:*
    1. Онбординг: предложение выбрать 3–5 любимых фильмов из популярного каталога.
    2. Если шаг пропущен: показ взвешенного бейзлайн-топа по рейтингу и популярности.
    3. Рекомендации по схожести жанров и метаданных выбранных картин.

* **Сценарий 2 (Прогретый пользователь / Warm User):**
  * В профиле накоплено 5+ оценок.
  * *Поведение системы:*
    1. Полноценная персонализация: учет истории оценок нейросетевой моделью.
    2. Двухуровневое ранжирование: быстрый отбор кандидатов + сортировка под вкусы профиля.
    3. Метки объяснения («Explainable AI»): почему фильм предложен.

* **Сценарий 3 (Семантический поиск по вайбу):**
  * Пользователь вводит запрос свободным текстом («дождливый неонуар под меланхолию»).
  * *Поведение системы:* расчет косинусного сходства между эмбеддингом запроса и эмбеддингами синопсисов, выдача наиболее близких картин.

## 2. Метрики качества

### 2.1. Офлайн-метрики (ML-оценка на валидации)
* **RMSE / MAE:** точность предсказания рейтинговых баллов.
* **HitRate@5:** наличие хотя бы одного релевантного фильма в топ-5 выдачи.
* **NDCG@5:** оценка релевантности с учетом позиции (чем выше хороший фильм, тем больше балл).
* **Каталожное разнообразие (Diversity):** исключение выдачи одних и тех же блокбастеров всем подряд.

### 2.2. Онлайн-метрики (продуктовые)
* **CTR (Click-Through Rate):** кликабельность кнопки «Что посмотреть» и карточек фильмов.
* **Conversion to Rating:** процент случаев, когда пользователь посмотрел фильм и сохранил оценку в профиль.

## 3. Архитектура и стратегия масштабирования

### 3.1. Фаза 1: Фокус на ML (Текущая, < 100 пользователей)
* **База данных:** SQLite через SQLAlchemy ORM (быстрый старт без поднятия серверов).
* **Векторный поиск:** эмбеддинги в оперативной памяти (NumPy / FAISS).
* **Инференс:** прямой расчет через веса PyTorch в FastAPI.

### 3.2. Фаза 2: Масштабирование (1 000+ пользователей)
* Переход на **PostgreSQL** без изменения бизнес-логики (за счет ORM).
* Вынос векторов в **Qdrant**.
* Кэширование персональных выдач и топов в **Redis**.

## 4. Схема данных (Data Schema)

### 4.1. Сущность User (Пользователь)
* `id` (INTEGER, Primary Key) — уникальный идентификатор.
* `username` (VARCHAR) — имя пользователя.
* `created_at` (TIMESTAMP) — дата регистрации.

### 4.2. Сущность Movie (Фильм)
* `id` (INTEGER, Primary Key) — уникальный идентификатор.
* `title` (VARCHAR) — название фильма.
* `release_year` (INTEGER) — год выпуска.
* `genres` (VARCHAR) — жанры.
* `overview` (TEXT) — текстовый синопсис для NLP-векторизации.
* `poster_url` (VARCHAR) — ссылка на обложку.

### 4.3. Сущность Rating (Оценка / Взаимодействие)
* `id` (INTEGER, Primary Key) — идентификатор события.
* `user_id` (INTEGER, Foreign Key -> User.id) — пользователь.
* `movie_id` (INTEGER, Foreign Key -> Movie.id) — фильм.
* `rating` (FLOAT) — оценка фильма.
* `timestamp` (INTEGER) — время проставления оценки (для time-based валидации).
